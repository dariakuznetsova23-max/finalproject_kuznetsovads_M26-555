# ValutaTrade Hub

Учебное консольное приложение для управления виртуальным валютным
портфелем и получения курсов из внешних API.

Репозиторий: `finalproject_kuznetsovads_M26-555`.

Приложение не выполняет реальные платежи и не предназначено для
использования с настоящими деньгами.

## Возможности

- Регистрация пользователей и вход.
- Хранение паролей в виде SHA-256 хешей с индивидуальной солью.
- Виртуальные кошельки USD, EUR, GBP, RUB, BTC, ETH и SOL.
- Пополнение виртуального USD-кошелька.
- Покупка валют за USD и продажа валют за USD.
- Оценка портфеля в выбранной базовой валюте.
- Прямые, обратные и кросс-курсы через USD.
- Загрузка криптовалютных курсов из CoinGecko.
- Загрузка фиатных курсов из ExchangeRate-API.
- История курсов и локальный кеш с TTL.
- Периодическое обновление отдельным процессом.
- Логирование с ротацией файлов.
- Автоматические офлайн-тесты.

## Требования

- Python 3.12 или новее.
- uv.
- Git для работы с репозиторием.
- Интернет для обновления курсов.
- API-ключ ExchangeRate-API для фиатных валют.
- При необходимости — Demo API key CoinGecko.

Команды ниже приведены для PowerShell.

## Установка

Клонируйте репозиторий, перейдите в его корневую папку и выполните:
```powershell
uv python install 3.12
uv sync --locked
```

`uv.lock` фиксирует версии зависимостей.

## Настройка API-ключей

ExchangeRate-API:
```powershell
$ApiKey = Read-Host "ExchangeRate-API key" -AsSecureString
$env:EXCHANGERATE_API_KEY = [System.Net.NetworkCredential]::new("", $ApiKey).Password
Remove-Variable ApiKey
```

CoinGecko, если требуется:
```powershell
$ApiKey = Read-Host "CoinGecko Demo API key" -AsSecureString
$env:COINGECKO_API_KEY = [System.Net.NetworkCredential]::new("", $ApiKey).Password
Remove-Variable ApiKey
```

Переменные действуют в текущем терминале и запускаемых из него процессах.
После открытия нового терминала их нужно задать заново.

Приложение не загружает `.env` автоматически.

Не сохраняйте ключи в исходном коде и не публикуйте их.

## Пример работы

Следующие команды вводятся внутри интерактивной оболочки:
```text
register --username alice --password 1234
login --username alice --password 1234
deposit --currency USD --amount 10000
update-rates
show-rates
get-rate --from BTC --to USD
buy --currency BTC --amount 0.001
show-portfolio
sell --currency BTC --amount 0.0004
show-portfolio
logout
exit
```

Если пользователь уже существует, повторная регистрация не требуется.

Пароль `1234` приведён только для учебного примера.
Используйте отдельные учебные пароли: команды видны на экране.

## Команды

| Команда | Назначение |
|---|---|
| `register --username NAME --password PASSWORD` | Регистрация |
| `login --username NAME --password PASSWORD` | Вход |
| `logout` | Выход из учётной записи |
| `deposit --currency USD --amount NUMBER` | Виртуальное пополнение USD |
| `buy --currency CODE --amount NUMBER` | Покупка валюты за USD |
| `sell --currency CODE --amount NUMBER` | Продажа валюты за USD |
| `show-portfolio --base USD` | Просмотр портфеля |
| `get-rate --from BTC --to EUR` | Получение свежего курса |
| `update-rates` | Обновление всех источников |
| `update-rates --source coingecko` | Обновление криптовалют |
| `update-rates --source exchangerate` | Обновление фиатных валют |
| `show-rates --currency BTC` | Фильтр курсов по валюте |
| `show-rates --top 3` | Криптовалюты с наибольшей ценой единицы |
| `show-rates --base EUR` | Курсы относительно EUR |
| `exit` | Завершение программы |

В `buy` и `sell` параметр `--amount` задаёт количество единиц валюты.

Дробные числа вводятся с точкой: `0.001`.

`show-rates --top` сортирует по цене единицы валюты, а не по
рыночной капитализации.

Сессия пользователя хранится в памяти процесса. Команды, требующие
входа, выполняйте в одной интерактивной сессии.

## Периодическое обновление

Запуск отдельного процесса:
```powershell
uv run valutatrade-parser --interval 300
```

Только криптовалюты:
```powershell
uv run valutatrade-parser --interval 300 --source coingecko
```

Остановка: `Ctrl+C`.

API-ключи должны быть заданы в терминале, из которого запускается
этот процесс. Интервал выбирайте с учётом лимитов своего тарифа.

## Курсы и TTL

Все полученные курсы приводятся к виду `CODE_USD`.

Если поставщик возвращает USD → EUR, приложение вычисляет
EUR → USD как обратную величину.

Кросс-курс вычисляется через USD:
```text
BTC → EUR = (BTC → USD) / (EUR → USD)
```

По умолчанию TTL составляет 300 секунд.

Устаревшие курсы не используются для торговли и оценки ненулевых
позиций портфеля. Команда `show-rates` может показывать их с явной
отметкой `УСТАРЕЛ`.

Временем снимка считается время получения ответа.
Время обновления поставщика, если доступно, хранится отдельно
в метаданных истории.

Если один источник недоступен, успешно полученные курсы другого
источника сохраняются.

## Хранение данных

Файлы создаются автоматически в `data/`:

- `users.json` — пользователи, соли и хеши паролей.
- `portfolios.json` — кошельки пользователей.
- `rates.json` — последний снимок курсов.
- `exchange_rates.json` — история наблюдений.
- `.storage.lock` — технический файл блокировки.

Запись выполняется через временный файл и атомарную замену.
Изменения защищены блокировкой между процессами.

Атомарность обеспечивается для одного файла. Изменения нескольких
файлов не являются полноценной транзакцией СУБД при аварийном
завершении системы.

Повреждённые JSON-файлы не перезаписываются автоматически.

Рабочие данные и логи исключены из Git.

## Настройки

Основные настройки находятся в `[tool.valutatrade]` файла
`pyproject.toml`:

- `data_dir`;
- `logs_dir`;
- `rates_ttl_seconds`;
- `default_base_currency`;
- `log_level`;
- параметры ротации логов;
- таймаут блокировки хранилища.

Дополнительно поддерживаются переменные окружения:

- `VALUTATRADE_DATA_DIR`;
- `VALUTATRADE_LOG_DIR`;
- `EXCHANGERATE_API_KEY`;
- `COINGECKO_API_KEY`.

Пути по умолчанию определяются относительно текущей рабочей папки.
Для описанных команд запускайте приложение из корня проекта.

## Архитектура
```text
valutatrade_hub/
├── core/
│   ├── currencies.py
│   ├── exceptions.py
│   ├── models.py
│   ├── rates.py
│   ├── usecases.py
│   └── utils.py
├── infra/
│   ├── database.py
│   └── settings.py
├── parser_service/
│   ├── api_clients.py
│   ├── config.py
│   ├── scheduler.py
│   ├── storage.py
│   └── updater.py
├── cli/
│   └── interface.py
├── decorators.py
└── logging_config.py
```

`core` содержит модели и бизнес-логику, `infra` — конфигурацию и
JSON-хранилище, `parser_service` — получение и сохранение курсов,
`cli` — разбор команд и вывод результатов.

Реализованные приёмы:

- Абстрактный класс `Currency` и полиморфные классы валют.
- Singleton для `SettingsLoader` и `DatabaseManager`.
- Декоратор `log_action` для операций с балансами.
- Замыкание `make_json_cache` для кеширования чтения JSON.

## Логи

- `logs/actions.log` — операции с балансами.
- `logs/parser.log` — обновления курсов.

Используется ротация: по умолчанию 1 МБ на файл и три резервных файла.
Пароли и API-ключи намеренно не включаются в сообщения приложения.

## Ограничения учебной версии

Используется `float`, поэтому возможны погрешности вычислений.
Для настоящих денежных расчётов нужен `Decimal`.

SHA-256 с солью реализован по учебному условию. Для настоящего
приложения следует использовать специализированный алгоритм
хеширования паролей, например Argon2id.

JSON-хранилище не заменяет транзакционную базу данных.
История курсов растёт без автоматического удаления старых записей.
Метаданные капитализации в реестре валют являются учебными,
а не актуальными рыночными значениями.

Доступность API зависит от сети, ключей и условий поставщиков.
